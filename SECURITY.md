# Политика безопасности

## 🔐 Threat model

EduTest Pro работает в локальной сети учебной аудитории. Реалистичные угрозы:

| Угроза | Кто атакует | Что может пойти не так |
|---|---|---|
| **Подмена сервера** | Студент с ноутбуком в той же подсети | Поднимает свой сервер на TCP 9876, рассылает «обновление» (произвольный `.exe`), которое клиенты автоматически выполняют → удалённое выполнение кода (RCE). |
| **Подмена клиента** | Студент-программист | Шлёт сфабрикованный пакет `result` от имени другого ученика и портит результат. |
| **Перехват трафика** | Сосед в той же сети | Видит вопросы и ответы (TCP в открытом виде). |
| **Кража результатов** | Любой клиент | `MAX_MESSAGE_SIZE = 500 МБ` без аутентификации → лёгкая DoS-атака. |
| **Path traversal в @image:** | Учитель, подгрузивший тест извне | `@image:../../etc/passwd` мог быть включён в сетевой payload. |
| **MITM при auto-update** | Любой в LAN | TCP без подписи бинарника → подмена обновления → RCE. |

## 🛡 Текущая защита (после ветки `improvements/audit-and-hardening`)

1. **Подпись обновлений (Ed25519).** Сервер подписывает каждый бинарник приватным ключом, клиент проверяет подпись встроенным публичным ключом до того, как **запустить** новый исполняемый файл. См. `shared/security.py`.
2. **Sandbox для `@image:`.** Парсер запрещает выход за пределы директории теста.
3. **Жёсткий лимит сообщения.** `MAX_MESSAGE_SIZE` снижен с 500 МБ до 64 МБ.
4. **Verified TLS.** При обращении к GitHub API больше не используется `ssl._create_unverified_context()` — вместо этого корневой store из пакета `certifi`.

## 🚧 Известные ограничения (нужно сделать в будущих релизах)

- **Аутентификация студента ↔ сервер.** Сейчас имя/группа = чистый текст без подписи. Минимум, что стоит добавить: общий `exam_token`, который преподаватель сообщает классу устно, и HMAC handshake.
- **Шифрование канала.** TCP сейчас открытый. Идеал — `QSslSocket` с самоподписанным сертификатом и pinned SHA-256 на стороне клиента.
- **XOR-«шифр» бэкапов.** `XORCipher` в `shared/styles.py` это **не шифр**, ключ захардкожен. Использовать только как обфускацию против случайного редактирования — никаких PII туда не класть. Для реальной защиты — `cryptography.fernet.Fernet` с ключом, выдаваемым преподавателем.

## 📞 Сообщить об уязвимости

Если вы нашли security-баг, **не открывайте публичный issue**. Напишите автору в личку через GitHub (раздел Issues → New issue → выберите «Private vulnerability report»), либо откройте Draft Security Advisory: <https://github.com/uiper123/tgtgtess/security/advisories/new>.

Минимально полезный отчёт: версия, ОС, шаги воспроизведения, ожидаемое и фактическое поведение.

## 🔑 Управление ключами подписи обновлений

```bash
# 1. Один раз сгенерировать пару ключей (приватный — хранить в секрете!).
python scripts/generate_signing_keys.py

# 2. Положить shared/update_public_key.pem в репозиторий (он не секретный).
git add shared/update_public_key.pem

# 3. Приватный ключ положить в ~/.edutest/update_private_key.pem на машине
#    преподавателя (chmod 600). НИКОГДА не коммитить.

# 4. При каждом релизе подписывать собранный бинарник:
python scripts/sign_update.py dist/student/TTGTiSO-Test-student.exe
# создаёт TTGTiSO-Test-student.exe.sig рядом.
```

Подписи проверяются клиентом автоматически. Если подпись отсутствует или невалидна — обновление **отклоняется**, а в лог пишется предупреждение.
